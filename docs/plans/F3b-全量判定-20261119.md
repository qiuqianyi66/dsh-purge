# F3b 全量判定（82 条）— 2026-11-19

结论：**升级档位判定为「不可能达到 ≥60%」**。65 个载体里可原生替代 24 个、免迁移 2 个，合计 **26/65 = 40.0%**；即使把 11 个只能「整行禁用」的 partial 全算上，上限也只有 **37/65 = 56.9%**，仍低于 60% 门槛所需的 39 个。按规划第 6 节，维持 **30%–60% 档**：只做 3 条试点、保留补丁主路径、继续加厚评测层。

## 1. 判定口径

| 判定 | 含义 |
| --- | --- |
| `native` | 官方扩展点能直接表达：Config 值、composition 行（insert/覆盖 config/disabled）、具名 section、waterfall 监听 |
| `partial` | 只能整行禁用等更强语义近似，等价性存疑 |
| `no-hook` | 效果写在包内常量、内部逻辑、或桌面壳/客户端时序，插件无入口 |
| `not-needed` | 补丁已 `retired` 或 `replacements: []`，无需迁移 |

判据只采两处：宿主安装包源码/Config（含 `.dshpurge.bak` 基线）与官方 `dsh-doc` 扩展点文档；推断一律不计入 native。

## 4. 与 F3 抽验的差异

- F3 抽验 18 条 → 12 可行，样本可行率 67%，但样本仅覆盖 22%。
- 全量后 native 26/82 = 31.7%，与抽验偏差来自：抽验偏向可判定的 Config 类，全量把桌面壳、回退、hooks、第三方适配的 no-hook 全暴露出来。

## 5. 对 Go/No-Go 与 F6 的影响

## 6. 已知边界（不得当结论）

- native 表示「官方入口能表达」，**不等于已实现或已验证**；等价性要等 F6 试点跑通。
- partial 的「整行禁用」是更强语义，不能算 60% 分子。
- 本判定不覆盖未安装的第三方插件行为；`hooks-*` 的等价性未验。
- 44 条 no-hook 中若有上游未来新增 Config/section，可重跑本脚本更新。
