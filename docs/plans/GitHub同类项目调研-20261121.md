# GitHub 同类项目调研：谁适配了 DSH rc.4 / rc.5

> 触发：用户要求「做之前先看看 GitHub 有没有已经适配的项目，直接学习」。
> 方法：横纵分析法——纵向看 dsh-purge 生态的版本演进，横向比各仓库对 rc.4/rc.5 的处理，再合轴判断能借鉴什么。
> 取证时间 2026-11-21；所有结论附可重放动作，未核实的一律标 unknown。

## 0. 一句话结论

**全生态没人适配到 rc.4 / rc.5**：最强的社区维护版把兼容声明停在 rc.3，其余 fork 更老。本仓库的 rc.5 离体适配（78 条 0 需重对齐 + 隔离树 G1–G6 + 锚点 7/7）目前是最靠前的一份。可学的不是「怎么做 rc.5」，而是**怎么把锚点漂移变成红灯**和**怎么诚实登记中间态**——两条都已落地。

## 2. 横向：他们怎么处理「补丁失配」和「版本声明」

### 2.1 社区维护版的锚点测试（值得学，已落地）

`test/patch-anchors.test.mjs` 的做法：

- 从**真实宿主**抄下锚点所在的那一行（`RESPONSES_INSTRUCTION_ROLE` 等），当 fixture 常量；
- 每条补丁跑 `applyReplacementsToText`，断言 `changed === true`，再跑一次断言 `changed === false`（幂等）；
- 关键注释：「The failure mode is invisible because the patch is `optional`, so a miss still reports as applied.」——**optional 补丁失配不报错**，这正是我们担心的假绿在对方那里的同构版本；
- 还有一层真机校验：`HOST_ROOTS` 存在时读真实文件、`node --check` 验语法、区分「已打过」与「该打没打」。

我们对应的落地：

- `scripts/rc5-fixture-gen.mjs`：从隔离树机械提取 rc.5 的锚点片段（`tool-fs` 三个常量 + Config schema 行 / base 组合的 sandbox 与 approval 行 / plan-mode `section:` 整段 / plan-mode 服务的 section 注册），找不到锚点直接 exit 2，**不静默产出空 fixture**；`--check` 只比内容不比日期，可进 CI。
- `fixtures/host-anchors-0.2.2-rc.5.json`：生成物，785 行内。
- `test/anchor-rc5.test.js`：7 条。`#22` 三个常量 → 目标值 + 幂等；`#7`/`#8` base 两行 → 翻转 + 幂等；`#63` 三段文案全替换 + 幂等；外加一条前提断言「rc.5 的 plan-mode 正文仍来自 `config.section`」——这是 F6 用组合配置替代 #63 的依据，一旦上游把正文内联进服务，这条会先红。
- 实效：脚本第一次跑就抓到一处真实差异（我按单引号假设 `name: 'plan:policy'`，rc.5 实际是双引号），说明这套机制不是形式主义。

### 2.2 社区维护版的逐版本声明（值得学，已落地）

`package.json`：

```json
"dsh": { "compatibility": {
  "dsh": ">=0.2.1-rc.1 <0.3.0",
  "dshReleases": { "0.2.1-rc.1": "compatible", …, "0.2.2-rc.3": "compatible" }
}}
```

好处：宿主视角逐版本给档位，未验就写 `unknown`，不必在「撒谎说已支持」和「完全不提」之间二选一。

我们对应的落地（`lib/compat-matrix.js`）：

- 新增 `DSH_RELEASES`：`supported` / `compatible-isolated` / `legacy` / `unknown` / `unsupported` 五档。rc.5 = `compatible-isolated`（契约 ✓ 实打 ✓ 冒烟 ✗ 真机 ✗），rc.4 = `unknown`（没单独跑，不外推）。
- 新增 `dshReleaseStatus(version)`。
- `validateCompatMatrix()` 加牙齿：`supported` 恰一条且必须等于 `COMPAT_CURRENT.dsh`；`compatible-isolated` 不许带 `hostSmoke: verified`（有就该升 supported）；必须带 `applySim: verified`（没实打不许占这个档）。
- `compat.json` 输出 `releases` 块；README 适配表不动（避免与既有渲染测试冲突），`gen-compat-readme --check` 仍绿。

为什么不改 `package.json` 的 `dsh.compatibility`：官方 bundle schema 没有这个字段，写进去不产生行为，只会变成第二份需要同步的声明。放在 `compat-matrix` + `compat.json` 里，是给 agent/CI 读的单一事实源。

## 3. 明确不学的部分（省得以后重复评估）

| 候选做法 | 拒绝理由 |
| --- | --- |
| `settleWhenAbsent` / `chainedAfter` 字段 | 我们已有等价物 `softSettle` 与补丁内链式注释，`test/anchor-rc3.test.js`、`test/diagnose-caliber.test.js` 已锁 |
| `PURGE_RC5_SOURCE` 整包读 `lib/index.js` 校验 | 他们验编译产物，我们要验源码 pattern；且默认路径是 macOS 的 |
| 直接换用社区维护版 | 补丁表是另一套编号（#32/#53/#57/#77/#80/#88/#89/#96），与 82 条台账不同源；`dshTarget` 语义停在 0.2.1-rc.1。只能学方法，不能换仓 |
| `AdamPlatin123/dsh-plugin-radar` 的 k8s 实测 | 它做插件生态存活探测，不做宿主版本适配，对 rc.5 无输入 |
