### 2.3 rc.4 语义变更的影响判定

`docs/upgrade-guide/v0.2.2-rc.4/workspace-write-boundary-follows-root`：`ctx.sandboxPolicy.resolve({session})` 改为返回 Session 工作目录，worktree 内 `workspace-write` 不再能写原仓库 `.git`；迁移手段是 `additionalWritableRoots` 或 Host 插件 `ctx.sandboxPolicy.registerWritableRoot`，且**Windows 忽略 additional writable roots**。

对本插件的影响：**不改变任何补丁写法**。本插件的沙箱类补丁（#6 / #15 / #61）是「直接放开写入」，不依赖 `workspaceRoot` 边界计算；该变更只影响依赖「边界内可写」语义的用法。

## 3. 为什么没把 rc.5 写进矩阵（这是有意的，不是漏了）

矩阵校验器只允许**恰好一条 `supported`**，且 `legacy` / `unsupported` 行不许写当前插件版本 —— 即模型是「**一个插件版本 = 一个 supported 宿主目标**」。

rc.5 的真机冒烟（hostSmoke）与设备验收（device）**未跑**，直接进 `supported` 违反红线 R2「未验证不得写已支持」。所以：

- 矩阵不动（`COMPAT_CURRENT` 仍是 `0.2.2-rc.3` / `1.2.10`）。
- 前瞻数字单独记在新字段 `COMPAT_VERIFICATION.upcoming`（含 audit 与 isolatedCycle 实测值、`hostSmoke: "not-run"`、`device: "not-run"`），**不与 rc.3 的真机数字混算**。
- `compat.json` 由脚本生成，会带上这个 `upcoming` 块，机器可读。

2. 面板「应用」→ 真机交互验收（这是 device 证据）。

4. 把原 rc.3 行降级为 `legacy`（plugin `1.2.10`），`COMPAT_VERIFICATION` 用 rc.5 真机数字整体替换。
5. `npm run compat:check` + `npm test` 全绿才算完成。
