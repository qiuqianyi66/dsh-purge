## 2. 已坐实的人性化缺陷（按影响排序）

| ID | 缺陷 | 实测/代码证据 | 影响 | 优先级 |
| --- | --- | --- | --- | --- |
| G1 | **卸载残留 insert** | 临时 profile 集成复现：`uninstallPurge` 后 `bundles` 已移除，但 `cordis.patch.yml` 里 `id: dsh-purge` 仍在；`lib/uninstall.js` 全文 0 处处理 insert | 下次启动 loader 遇到指向已删包的 insert，可能启动报错或静默跳过 | P0 |

| G3 | 安装写 profile 无备份、非原子 | `ensureProfileBundles` / `ensureProfileBodyInsert` 直接 `writeFileSync` | 断电/崩溃可能留下半截 JSON/YAML | P0 |
| G4 | postinstall 静默成功 | `ensure-profile-bundle.mjs` 找不到 profile 直接 return，退出码 0 | 用户以为装好，实际没注册 | P0 |

| G13 | 只做 Windows | 无 `install.sh`；profile 路径/keychain 未验 | macOS 用户体验断层 | P2 |
| G14 | 工程术语直出 | 「载体」「口径」「未审计」直接进面板/CLI | 非目标用户看不懂 | P2 |

## 3. 目标态：一次动作，插件自己出现

```
下载/克隆 → 双击 install.cmd（或 node bin/dsh-purge.js --install）
  ├─ 自动定位 DSH_HOME（环境变量 → 注册表 → 运行中进程 → ~/.dsh）
  ├─ 列出所有 profile，默认选「正在运行的那个」，其余提供 --profile
  ├─ 备份 package.json / cordis.patch.yml
  ├─ 复制插件到 profiles/<p>/dsh-purge-vendor（离线，不依赖 pnpm）
  ├─ 写 dependencies link、dsh.profile.bundles、cordis.patch.yml insert、allowBuilds
  ├─ 读回校验 4 项（vendor 版本 / dependency / bundles / insert）
  ├─ 完全退出 DSH → 重新启动（--restart；可 --no-restart）
  └─ 启动后自检 6 项，输出「面板已就绪 / 宿主 70 条已打 / 0 漂移」
失败时：自动回滚到备份，打印一屏人话原因 + 日志路径，退出码非 0
```

硬边界：安装器**不自动点「应用」**、不改官方远程仓库、不静默删用户文件。

| 文件 | 改动 |
| --- | --- |
| `lib/install.js`（新） | `detectDshHome` / `listTargetProfiles` / `installProfile` / `verifyInstall` / `restartDsh` |
| `lib/profile-insert.js` | 新增 `removeProfileBodyInsert`；`writeFileAtomic`（临时文件 + rename + `.bak-时间戳`）；insert 失败时不再静默，返回可复制的合并片段 |
| `lib/uninstall.js` | 调 `removeProfileBodyInsert`；报告 `insert_removed`；校验「profile 里 0 处 dsh-purge 引用」 |
| `bin/dsh-purge.js` | 新增 `--install [--profile <name>] [--restart] [--dry-run] [--json]` |
| `install.cmd` / `install.sh`（新） | 双击入口；找 Node 的顺序：DSH 内置 runtime → PATH；结束时 pause 保留窗口 |
| `test/install-autoload.test.js`（新） | 临时 DSH_HOME：全新安装 / 重复安装幂等 / 双 profile / 未知 YAML 拒绝并回滚 / 卸载后 0 残留 |
| `README.md` + `README.en.md` | 安装段顶部换成「一条命令」；保留手工兜底 |
| `scripts/pack-check.mjs` | 更新期望文件数（新增 3 个文件） |

验收（必须全部实跑）：
1. 临时 DSH_HOME + 空 profile：一条命令后 4 项校验全过；重复执行不再改动任何文件。
2. `--dry-run` 不写盘。
3. 未知 flow YAML：中止安装、原文件哈希不变、打印可复制的 insert 片段。
4. 安装后立刻卸载：`package.json` 与 `cordis.patch.yml` 里 `dsh-purge` 引用为 0；重启无 loader 报错。
5. 251+ 测试全绿；四道 check 全绿。

## 5. 路线分期

**P0 · 1.2.12（本轮先做）**：G1–G5 + G16 的安装期错误翻译。目标是把「拉下来→双击→面板出现」变成 0 手工步骤。

**P1 · 1.3.0**：G6–G10、G15。`doctor` 一屏体检（宿主/兼容/补丁/备份/insert/权限）+ `--fix`；首启向导两选一；未知宿主服务端拦截（`--force-unknown` 才放行）；一键导出诊断 zip。

**P2 · 1.3.x**：G11–G14。备份管理（显示占用、仅保留最近一份 asar）；每日一次静默更新检查 + 一键更新；macOS/Linux 安装器；面板文案做「人话层」。

**并行的技术线（不挤占 P0）**：
- **E4 评测层接官方观测**仍是最高优先：rc.3→rc.5 实测 0 条 pattern 失配，说明「字面量追版本」不再是主要风险；真正会「打上了但效果变了」的是语义（`workspace-write` 边界、`CONTENT_REFUSED`、subagent 模型读取）。
- E3 原生迁移只推进 #22/#63 的运行时 GWT，再谈开关上真机；#9 维持补丁。
- E1 雷达进 CI（每次上游发版自动跑 `upstream:radar` + `audit:next`）。
- E6 退役清单在 1.2.12 一并从活跃台账标注（不删定义，保留兼容）。

## 6. 决策点（需要用户确认）

1. 安装器默认**自动重启 DSH** 还是只提示？建议：双击入口默认重启并 5 秒倒计时可取消；`--no-restart` 可关。
2. 已有 tarball 安装的用户，是否统一迁到 `vendor` 布局？建议：安装器检测到 URL 依赖时保留依赖、只补 vendor 与注册（不强行改 lock）。
3. `install.cmd` 是否接受「找不到 DSH」时引导手输安装路径？建议：是，最多问一次。
